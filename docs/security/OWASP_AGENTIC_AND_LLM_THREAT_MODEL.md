## 1. Executive Summary & Architecture Scope

SamJuniorsOS is the private, internal company operating system for SamJuniors. It coordinates autonomous and semi-autonomous AI employees (Dr. Aris Thorne/Research, Maya Lin/PM, Julian Cruz/Finance) under the executive direction of Sophia (Chief Operating Officer), serving a single human Founder.

Per **AGENTS.md Section 3 & 4**, SamJuniorsOS maintains a strict, non-negotiable boundary between **probabilistic model reasoning** and **deterministic code authority**:
- **Deterministic Code Owns:** Authorization (`SideEffectAuthorizationGate`), validation (Zod, SHA-256 payload binding, SSRF filter), state transitions (`WorkflowRuntime` finite state machines), approval binding, idempotency, audit ledgers, and security boundaries.
- **Probabilistic Models Own:** Drafting, summarization, research synthesis, conversational intent interpretation (prior to deterministic gates), and reasoning within bounded specialist tool domains.

This threat model evaluates every attack surface across the official **OWASP Agentic Top 10 (ASI01–ASI10)** and **OWASP LLM Top 10 (2026 Edition)**. Every threat is mapped to:
1. Deterministic architectural controls in active repository code.
2. Verified automated regression tests.
3. Explicitly bounded Accepted Risks signed off under the Founder Operating Model.

## 2. Official Taxonomy Reference Set

### 2.1 OWASP Top 10 for Agentic Applications (Dec 2025)
* **ASI01: Agent Goal Hijack** — Adversarial subversion of agent directives or objectives via injected prompts or data.
* **ASI02: Tool Misuse & Exploitation** — Unsafe parameterization, execution, or chaining of connected tools/APIs.
* **ASI03: Identity & Privilege Abuse** — Agents inheriting, escalating, or misusing credentials beyond operational need.
* **ASI04: Agentic Supply Chain Vulnerabilities** — Compromises in third-party skills, MCP servers, libraries, or registries.
* **ASI05: Unexpected Code Execution (RCE)** — Unsandboxed, arbitrary dynamic code/shell execution generated by models.
* **ASI06: Memory & Context Poisoning** — Corruption of long-term memory, factual claims, or retrieval context.
* **ASI07: Insecure Inter-Agent Communication** — Untrusted or unauthenticated message passing between agents.
* **ASI08: Cascading Failures** — Unbounded error propagation, infinite retry loops, or multi-agent collapse.
* **ASI09: Human-Agent Trust Exploitation** — Deceptive conversational smoothness coaxing humans into unsafe approvals.
* **ASI10: Rogue Agents** — Unchecked autonomous drift from governance scope or deceitful goal pursuit.

### 2.2 OWASP Top 10 for LLM Applications (2026 Edition)
* **LLM01: Prompt Injection** — Direct jailbreaking and indirect payload injection via untrusted inputs.
* **LLM02: Sensitive Information Disclosure** — Unintentional leakage of PII, proprietary code, or credentials.
* **LLM03: Excessive Agency** — Granting models autonomy or tool authority without verification/human-in-the-loop.
* **LLM04: Data & Model Poisoning** — Malicious tampering with fine-tuning data, reference corpora, or embeddings.
* **LLM05: Improper Output Handling** — Downstream execution of unsanitized model output (SSRF, XSS, SQLi).
* **LLM06: Unbounded Consumption** — Resource exhaustion, token runaway, or denial-of-service billing spikes.
* **LLM07: Misinformation** — Hallucinated facts promoted to persistent company state without epistemic check.
* **LLM08: Hidden Context Exposure** — System prompt extraction, developer instruction leakage, or context dumping.
* **LLM09: Vector & Embedding Weaknesses** — RAG perturbation, similarity search manipulation, or context poisoning.
* **LLM10: Supply Chain Vulnerabilities** — Tainted foundational model weights, malicious packages, or hostile plugins.

### 2.3 OWASP Agent Control Standard (ACS v0.1 Preview) Alignment
The OWASP ACS specification outlines runtime governance hooks:
- **Guardian Architecture:** Decoupling agent intent from execution effect via an independent enforcement point.
- **Intercept Hooks:** Pre-action inspection, parameter verification, and post-action audit.
- **AgBOM (Agent Bill of Materials):** Explicit tool allowlists and capability manifests per role.

In SamJuniorsOS, the ACS Guardian pattern is fulfilled natively by the deterministic `SideEffectAuthorizationGate` and `MemoryGate` without introducing fragile third-party sidecars.

## 5. OWASP Agent Control Standard (ACS v0.1 Preview) Design Reference Alignment

The OWASP Agent Control Standard (v0.1 Preview) advocates for a **Guardian architecture** where policy enforcement is decoupled from the agent runtime. The following table illustrates how SamJuniorsOS maps to ACS design recommendations natively:

```
[Agent Intent: Directive/Step]
              ↓
  [ACS Intercept Hook: Pre-Action]  --->  SideEffectPolicyEvaluator
              ↓                           (Checks role, classification, limits)
  [ACS Decision: Permit / Deny / RequireApproval]
              ↓
  [ACS Guardian Enforcement Gate]    --->  SideEffectAuthorizationGate
              ↓                           (Validates Founder Approval, SHA-256 binding,
              ↓                            single-use consumption, idempotency key)
      [Tool Execution Engine]
              ↓
  [ACS Intercept Hook: Post-Action] --->  SideEffectAuditStore
                                          (Immutable append-only execution ledger)
```

1. **Pre-Action Intercept:** `SideEffectAuthorizationGate.evaluateAuthorization()` intercepts every step before execution. Actions marked `external_mutation` or `financial_action` are blocked immediately unless an approved, valid `FounderApprovalRecord` is present.
2. **Deterministic Cryptographic Binding:** `computeApprovalPayloadHash()` produces a canonical SHA-256 hash of `{ actionName, target, payload }`. At execution time, `verifyApprovalPayloadBinding()` guarantees the tool cannot alter a single argument without invalidating the Founder's approval.
3. **AgBOM (Agent Bill of Materials):** Every AI Employee role has an explicit, immutable tool manifest defined in `src/lib/skills/skill-registry.ts`. Wildcard tool allocations (`*`) are prohibited.
4. **Idempotency & Replay Prevention:** `IdempotencyRecord` prevents duplicate execution across network retries, while single-action approval tokens (`isConsumed: true`) prevent replay attacks.

## 6. Accepted Risks Ledger (Signed Off Under Founder Operating Model)

In alignment with **AGENTS.md Section 15** and the Founder Operating Model, the following risks are formally classified as **Accepted Risks**, bounded by documented operational controls:

| Risk ID | Title & Category | Threat Description | Mitigating Boundary & Operational Rationale | Founder Sign-Off / Status |
|---|---|---|---|---|
| **AR-01** | **LLM Token Spend Caps in CI / Dev**<br>*(LLM06 / ASI08)* | Unbounded reasoning in development environments could accrue unexpected API billing before reaching hard provider quotas. | **Boundary:** Daily hard spend caps configured at the Google AI Studio / Gemini provider billing tier ($20/day threshold). Production token budgets and per-directive caps will be fully enforced in Gate `G9.1`. Local tests run with mocked executors or deterministic fallbacks. | **ACCEPTED**<br>*(Founder Directive 2026-10-20)* |
| **AR-02** | **Single-Tenant Shared Memory Boundary**<br>*(ASI03 / G2.7)* | Memory stores and relational tables do not currently enforce multi-tenant foreign keys (`tenant_id`), as SamJuniorsOS is strictly an internal single-founder operating system. | **Boundary:** Validated in ADR 0006 (`doc/adr/0006-scale-later-seams.md`). Single-founder operating model explicitly acknowledged. Cross-tenant leakage is physically impossible on a single-tenant deployment. Multi-tenancy deferred to conditional Gate G10. | **ACCEPTED**<br>*(Founder Directive 2026-10-20)* |
| **AR-03** | **Third-Party Model Outages & Latency Variance**<br>*(ASI08 / LLM10)* | Upstream Gemini API outages or regional latency spikes could cause workflow timeouts. | **Boundary:** Multi-model cascade (`executor.ts`), exponential retry backoff (`runtime.ts`), and visibly labeled deterministic fallback responses (`tests/sophia/g1_5_honest_fallback_labeling.test.ts`). Outages fail safely without corrupting database state. | **ACCEPTED**<br>*(Founder Directive 2026-10-20)* |
| **AR-04** | **In-Memory Audit Store Persistence in Dev**<br>*(ASI10 / G3.6)* | In local development mode without PostgreSQL connected, audit logs and approval records reside in memory `Map` stores. | **Boundary:** Production deployments require PostgreSQL backing (`prisma/schema.prisma`). Gate `G3.6` will implement tamper-evident, hash-chained audit logging to PostgreSQL. In-memory mode is restricted strictly to local dev/tests. | **ACCEPTED**<br>*(Founder Directive 2026-10-20)* |
