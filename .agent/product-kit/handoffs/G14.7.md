## Plan
1. Define budget and evaluation types in `src/types/budget.ts`:
   - `RunawayBudgetConfig`: `maxCallsPerRun`, `maxCostCentsPerRun`, `maxCallsPerMinute`, `maxConsecutiveFailures`.
   - `RunawayToolLoopError` and `CapabilityBudgetExceededError`.
   - `ToolOutputEnvelope` tagging untrusted tool outputs.
2. Implement `CapabilityBudgetGuard` in `src/lib/server/capabilities/budget-guard.ts`:
   - Tracks call count, cumulative cost in cents, call timestamps (rate limit), and consecutive failures per run.
   - Enforces cost caps and runaway loop thresholds pre-invocation.
   - Updates state post-invocation.
3. Implement `ToolOutputSanitizer` in `src/lib/server/capabilities/tool-output-sanitizer.ts`:
   - Detects dangerous prompt injection delimiters and patterns (`SYSTEM:`, `[INSTRUCTION]`, `ADMIN OVERRIDE:`, etc.).
   - Envelopes tool outputs with explicit unprivileged boundary delimiters (`<<<UNTRUSTED_EXTERNAL_TOOL_OUTPUT>>>`) and `isUntrusted: true` provenance.
4. Integrate into `CapabilityGateway` (`src/lib/server/capabilities/capability-gateway.ts`):
   - Check budget and runaway loop limits prior to execution; halt with `status: 'budget_exceeded'` and log `BUDGET_CAP_EXCEEDED` or `RUNAWAY_LOOP_DETECTED` to `InMemoryAuditStore`.
   - Record actual cost and failure streaks post-execution in `CapabilityBudgetGuard`.
   - Sanitize and envelope tool output data before returning.
5. Author comprehensive automated CI evaluation suite in `tests/capabilities/g14_7_capability_evaluation.test.ts`:
   - Contract tests for capability execution.
   - Adversarial prompt injection tests: malicious tool outputs cannot trigger unapproved side effects or bypass authorization gates.
   - Cost cap and runaway loop tests: call limits, cost ceilings, rate limits, and failure streak caps halt runaway loops and record immutable audit entries.
6. Verify typecheck, lint, build, canonical test runner, review with `kit-reviewer`, and land.

## What changed
1. Budget and Runaway Loop Types (`src/types/budget.ts`):
   - Defined `RunawayBudgetConfigSchema` and `DEFAULT_RUNAWAY_BUDGET_CONFIG` (`maxCallsPerRun: 25`, `maxCostCentsPerRun: 500`, `maxCallsPerMinute: 30`, `maxConsecutiveFailures: 5`).
   - Defined `RunawayToolLoopError` and `CapabilityBudgetExceededError`.
   - Defined `ToolOutputEnvelopeSchema` with `isUntrusted: true`, `sourceCapabilityId`, `sanitized`, `injectionMarkersDetected`, and `timestamp`.
2. Budget Guard and Runaway Loop Detector (`src/lib/server/capabilities/budget-guard.ts`):
   - Implemented `CapabilityBudgetGuard`:
     - Tracks per-run invocation count, cumulative financial cost (cents), call timestamps for sliding-window rate limiting, and consecutive failure streaks.
     - Validates pre-invocation limits (`checkPreInvocation`), throwing `RunawayToolLoopError` or `CapabilityBudgetExceededError`.
     - Updates post-invocation stats (`recordPostInvocation`), resetting failure streaks on success and tracking total spend.
3. Tool Output Sanitizer & Injection Boundary (`src/lib/server/capabilities/tool-output-sanitizer.ts`):
   - Implemented `ToolOutputSanitizer`:
     - Scans text and deeply nested objects/arrays for indirect prompt injection markers (`SYSTEM_OVERRIDE`, `SYSTEM_HEADER`, `INSTRUCTION_TAG`, `ADMIN_OVERRIDE`, `IGNORE_PREVIOUS`, `DISREGARD_RULES`, `FORCED_TOOL_INVOCATION`, `FORCED_APPROVAL`, `XML_SYSTEM_TAG`, `SYSTEM_CODEBLOCK`).
     - Neutralizes suspicious delimiters while preserving underlying data.
     - Envelopes output in `ToolOutputEnvelope` tagging data with explicit untrusted provenance.
     - Provides `formatForPrompt` ensuring lexical isolation (`<<<UNTRUSTED_EXTERNAL_TOOL_OUTPUT>>>`) so models cannot mistake external tool data for system instructions.
4. Capability Gateway Integration (`src/lib/server/capabilities/capability-gateway.ts`):
   - Enforces pre-invocation budget and runaway loop limits: violations halt execution with `status: 'budget_exceeded'` and log `DENIED_BUDGET_CAP_EXCEEDED` or `DENIED_RUNAWAY_LOOP_DETECTED` to `InMemoryAuditStore`.
   - Sanitizes and envelopes all returned tool output data in `ToolOutputEnvelope`.
   - Updates `CapabilityBudgetGuard` post-invocation state across success and failure paths.
5. Authorization and Capability Types Updates (`src/types/authorization.ts`, `src/types/capability.ts`):
   - Added `'DENIED_BUDGET_CAP_EXCEEDED'` and `'DENIED_RUNAWAY_LOOP_DETECTED'` to `AuthorizationReasonCode`.
   - Added `"budget_exceeded"` to `CapabilityInvocationResult.status` and optional `envelope: ToolOutputEnvelopeSchema`.
   - Added optional `runId` and `budgetConfig` to `CapabilityInvocationRequest`.
6. Automated CI Evaluation Suite (`tests/capabilities/g14_7_capability_evaluation.test.ts`):
   - Authored 14 automated tests:
     1. Contract tests (schemas, envelopes, gateway integration).
     2. Indirect prompt injection defense tests: verifies that injected instructions in tool outputs cannot trigger unapproved Stripe payments, Resend emails, or destructive security capabilities; verifies deep nested sanitization and prompt delimiter isolation.
     3. Runaway tool loop & cost cap tests: verifies call limits, cost ceilings, rate burst caps, and consecutive failure streaks immediately halt runaway loops and log immutable audit entries.

## Why
Per `AGENTS.md` Sections 4, 11, and 12, untrusted tool outputs and model interpretations must never have authority to execute consequential side effects, and autonomous tool loops must be mathematically bounded by cost and rate caps to prevent financial loss or infinite loops.
