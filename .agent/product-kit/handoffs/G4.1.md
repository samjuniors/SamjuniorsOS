# G4.1: Company Brain as the single read and write path; retire parallel legacy paths

Exit evidence required: Static and runtime proof that no code path reads or writes company state outside the Brain; old paths removed.

## Plan
1. Create `src/lib/server/brain/company-brain.ts` (and `src/lib/server/brain/index.ts`) establishing `CompanyBrain` as the authoritative single read/write interface for Company State, Company Knowledge, Company Precedents (Memory), Decisions, and Epistemic Facts.
2. Encapsulate `CompanyStateStore` behind `CompanyBrain`: expose operational state getters (`getInitiatives`, `getFinancialMetrics`, `getProducts`, `getCustomers`, `getAttentionItems`, `getEmployees`, `getDecisions`, `queryState`) and atomic mutation setters (`setInitiatives`, `updateFinancialMetrics`, `updateProducts`, `updateCustomers`, `updateAttentionItems`, `recordDecision`).
3. Retire parallel legacy paths:
   - Retire the unpersisted module-level arrays (`serverRecentIntelligence`, `serverEngineeringIntelligence`) in `CompanyContextProvider` and route intelligence capture through `CompanyBrain` with durable evidence references.
   - Refactor `CompanyContextProvider` into a pure presentation formatter delegating all operational state directly to `CompanyBrain`.
   - Update `SophiaContextAssembler` (slice 1), `SophiaServerGateway` (domain: company_metrics), and `greeting.ts` to read operational state exclusively via `CompanyBrain`.
4. Ensure `spend-settings.ts` does not perform un-coordinated direct writes to `company_state`: route spend settings queries and persistence cleanly through `CompanyBrain` / `CompanyStateStore`.
5. Add comprehensive static and runtime verification suite `tests/platform/company_brain_single_path.test.ts`:
   - Static AST / grep proof verifying zero server code paths perform direct unmediated writes or reads to company state outside `CompanyBrain`.
   - Runtime test verifying that updates via `CompanyBrain` propagate atomically across all projections, persist across simulated restarts, maintain personal mind isolation, and enforce fail-closed authority.
6. What will NOT be done: No schema changes, no new external dependencies, no modification of personal mind invariants or authorization gates.
