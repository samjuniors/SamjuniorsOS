Exit evidence required: A settings page edits the limits; a test proves an unset cap means no autonomous model spend and that lowering the cap stops a running task; every change is logged as a founder action. The founder said on 2026-10-20 that the daily spend cap will be adjusted in settings.

## Plan
1. Core Deterministic Enforcement in `src/lib/server/agents/executor.ts`:
   - Enforce `SpendSettingsManager.getInstance().canExecuteAutonomousSpend()` before executing autonomous agent tasks:
     - If spend cap is unset (null) or reached, deterministically block execution before calling any LLM.
     - Record run in `AgentRunStore` with `status: 'halted'`, 0ms duration, and unverified provenance.
   - Register active worker execution with `SpendSettingsManager.getInstance().registerRunningTask(runId, taskAbortController, context.taskTitle)` so lowering the cap or reaching spend limit immediately aborts in-flight execution.
   - Unregister in `finally`.
   - Record autonomous spend in `SpendSettingsManager` on successful run completion.
2. Extend `SpendSettingsManager` in `src/lib/server/sophia/spend-settings.ts`:
   - When updating spend cap (`updateSpendCap`):
     - If the cap is unset (`newCap === null`) while tasks are running, halt running tasks.
     - If lowered below current spend or lowered below previous cap, halt running tasks and trigger stop control.
     - Maintain fail-closed audit recording before persisting setting to disk.
3. API Endpoints:
   - Enhance `src/app/api/sofia/spend/route.ts` (and `src/app/api/sophia/spend/route.ts`):
     - GET returns settings, breakdown, `canRunAutonomous`, `autonomyRules`, and `auditHistory`.
     - POST supports updating `spendCap` and `autonomyLevel`.
   - Create dedicated `src/app/api/sofia/autonomy/route.ts` and `src/app/api/sophia/autonomy/route.ts`:
     - GET returns `autonomyRules`.
     - POST updates autonomy level with founder decision ID, quote, and reason.
   - Register routes in `src/server/api.ts` for Express server parity.
4. Settings UI in App:
   - Enhance `src/sofia/ui/SettingsSheet.tsx` and `src/components/SettingsDrawer.tsx` under "Spend & Autonomy Limits":
     - Spend cap controls: numeric input, Clear (unset) button, presets ($5, $10, $25, $50), Save button, live metrics grid, status badge.
     - Autonomy policy controls: current level badges per action class (`read`, `draft`, `internal_write`, `external_reversible`, `external_hard_to_reverse`, `financial_legal`, `destructive_security`), preset buttons, founder quote/decision ref input, update button.
   - Enhance `src/os/components/os/DesktopOS.tsx` settings popover to display spend & autonomy limits summary.
5. Automated Verification Suite:
   - Author `tests/sophia/g12_8_autonomy_and_spend_settings.test.ts` covering all 6 phases:
     - Phase 1: Settings API & UI Contract Verification.
     - Phase 2: Unset spend cap strictly prohibits autonomous model spend.
     - Phase 3: Interactive spend tracked and permitted with unset cap.
     - Phase 4: Lowering spend cap halts running tasks mid-flight.
     - Phase 5: Every modification logged as tamper-evident founder action.
     - Phase 6: Deterministic Autonomy Policy elevation and governance enforcement.
6. Verification, typecheck, lint, build, independent review.

## What changed
- `src/lib/server/sophia/spend-settings.ts`:
  - Added `getRunningTasksCount(): number` reporting active registered tasks.
  - Enhanced `updateSpendCap`: when clearing the cap (`newCap === null`), immediately triggers stop control and halts active tasks, enforcing the invariant that with no cap set, no autonomous spend runs.
  - Maintained fail-closed immutable audit logging to `InMemoryAuditStore` before saving settings mutations.
- `src/lib/server/agents/executor.ts`:
  - Added autonomous spend pre-check: evaluates `canExecuteAutonomousSpend()`. If disallowed, blocks task immediately with `status: 'halted'`, duration 0ms, and unverified provenance without invoking LLM providers.
  - Registered active worker execution with `SpendSettingsManager.registerRunningTask(runId, taskAbortController, context.taskTitle)` and unregistering in `finally`.
  - Added task abort controller racing during `generateJson` so cap lowering aborts workers mid-flight immediately.
  - Added autonomous spend tracking (`spendManager.recordSpend({ amountUsd: 0.005, type: 'autonomous', taskId: runId, model })`) on task completion.
- `src/app/api/sofia/spend/route.ts` & `src/app/api/sophia/spend/route.ts`:
  - GET returns `autonomyRules: AutonomyPolicyEngine.getInstance().getAllRules()` along with `settings`, `canRunAutonomous`, `isCapReached`, and `auditHistory`.
