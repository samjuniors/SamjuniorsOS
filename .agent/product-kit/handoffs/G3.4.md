Exit evidence required: Headers verified on a running build; limits tested; audit step in CI.

## What changed
- `src/lib/server/security/rate-limiter.ts`:
  - Implemented `MemoryRateLimiter` using a deterministic sliding-window algorithm.
  - Returns RFC/IETF draft standard headers: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`, and `Retry-After`.
  - Configured distinct policies:
    - `STANDARD_API`: 120 req/min (2 req/s average)
    - `EXECUTIVE_API`: 60 req/min (1 req/s average) for privileged executive endpoints
    - `CRON_MACHINE`: 600 req/min (10 req/s average) for scheduler heartbeat POSTs
  - Implemented automatic TTL eviction (>120s) and hard ceiling memory bounds (10,000 keys) to protect against state-exhaustion denial of service.
  - Implemented `getClientIdentifier` with reverse-proxy header precedence (`cf-connecting-ip`, `x-forwarded-for`, `x-real-ip`).
- `src/proxy.ts`:
  - Enforced mutation request body size limits on POST/PUT/PATCH:
    - Standard API routes: 2 MB (`MAX_STANDARD_BODY_BYTES`)
    - Upload & media routes: 10 MB (`MAX_UPLOAD_BODY_BYTES`)
    - Rejects oversized requests immediately with HTTP 413 (`Payload Too Large`) and informative JSON error payload before body buffering.
  - Enforced rate limiting on `/api/*` routes with 429 Too Many Requests response on breach.
  - Added comprehensive `Content-Security-Policy` (CSP) header specifying:
    - `default-src 'self'`, `script-src 'self' 'unsafe-eval' 'unsafe-inline'`, `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com`
    - `font-src 'self' https://fonts.gstatic.com data:`, `img-src 'self' data: blob: https://picsum.photos https://images.unsplash.com`
    - `media-src 'self' blob: data:`, `connect-src 'self' https: wss: ws:`
    - `frame-ancestors 'none'` (or `'self'` for prototype assets), `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`
  - Attached all security headers and `x-request-id` to every response path, including early error returns (401, 413, 429).
- `next.config.ts`:
  - Configured server-level security headers for all routes (`/:path*`) including `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, and `X-DNS-Prefetch-Control`.
- `scripts/audit-deps.mjs`:
  - Created reproducible dependency audit script executing `npm audit --audit-level=critical`. Handles ephemeral package-lock generation when missing and guarantees zero critical supply-chain vulnerabilities.
- `package.json`:
  - Added `"audit:deps": "node scripts/audit-deps.mjs"`.
- `.github/workflows/ci.yml`:
  - Added `Dependency security audit` step running `npm run audit:deps` in the GitHub Actions CI pipeline.
- `tests/sophia/g3_4_security_headers_and_limits.test.ts`:
  - Authored 17 automated tests verifying security headers, CSP directives, prototype framing, error path header retention, 2MB/10MB body size limits, rate limiting headers, decrement behavior, 429 status code and retry-after, memory bounding, machine auth quota, audit script execution, and CI workflow configuration.

## Why
- In Milestone M2 ("Sofia works when your PC is off"), Sofia is exposed as an always-on cloud server. Exposing the system without strict Content Security Policy, mutation body size caps, rate limiting, and dependency vulnerability audits creates vulnerabilities to OWASP ASI06 / LLM06 (unbounded consumption), Denial of Service via buffer exhaustion, clickjacking, and supply chain threats. These controls enforce fail-closed security invariants at the gateway.
