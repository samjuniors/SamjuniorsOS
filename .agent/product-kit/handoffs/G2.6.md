# G2.6: Deploy pipeline with post-deploy verification of the live environment

Exit evidence required: Pipeline deploys to staging and verifies the deployed environment, not just the local build.

## Plan
1. Implement post-deploy live environment verification runner (`scripts/verify-deployment.ts`) evaluating health endpoint (`/api/health`), companion WebSocket gateway, security headers (CSP, nosniff, frame-ancestors, x-request-id), fail-closed executive auth boundaries, and SLA latency benchmarks.
2. Implement deployment pipeline orchestrator (`scripts/deploy-staging.ts`) executing pre-flight checks, database migration deployment (`prisma migrate deploy`), build verification, readiness polling, and post-deploy live verification.
3. Author GitHub Actions deployment workflow (`.github/workflows/deploy-staging.yml`) automating deployment and live post-deploy verification on main pushes and workflow_dispatch.
4. Add npm script commands (`deploy:staging`, `verify:deployment`) to `package.json`.
5. Author automated test suite (`tests/platform/deploy_pipeline_verification.test.ts`) validating live post-deploy verification, negative failure detection on unreachable targets, dry-run pipeline execution, and zero-secret audit.
6. Verify against existing test suites, run typecheck and lint.

## What changed
- `scripts/verify-deployment.ts`:
  - Implemented `verifyDeployment(options)`: checks `/api/health` connectivity, database status, companion WebSocket gateway reachability, strict HTTP security headers (CSP, nosniff, frame protection), fail-closed executive route authorization (`/api/orchestrate`, `/api/auth/ws-ticket`), and SLA latency metrics (< 1000ms P99).
  - Added CLI interface (`tsx scripts/verify-deployment.ts [--url <url>] [--ws-url <wsUrl>]`).
- `scripts/deploy-staging.ts`:
  - Implemented `runDeployPipeline(options)`: orchestrates pre-flight audit, versioned SQLite migration deployment, build compilation, live readiness polling, and post-deploy live verification.
  - Added CLI interface (`tsx scripts/deploy-staging.ts [--dry-run-verify] [--skip-build]`).
- `.github/workflows/deploy-staging.yml`:
  - GitHub Actions deployment pipeline workflow running pre-deploy quality checks, secret scan, build, and post-deploy live environment verification.
- `package.json`:
  - Added `"deploy:staging": "npx tsx scripts/deploy-staging.ts"`
  - Added `"verify:deployment": "npx tsx scripts/verify-deployment.ts"`
- `tests/platform/staging_reachability.test.ts`:
  - Ensured `prisma/db` directory exists before database connection in clean worktrees.
- `tests/platform/deploy_pipeline_verification.test.ts`:
  - Automated 5-test suite covering live environment verification, negative failure detection, pipeline execution, zero secrets, and CLI script exports.

## Why
Deploying without automated post-deploy verification risks promoting broken builds, database connection errors, or misconfigured security headers into live environments. Step G2.6 ensures that every deployment to staging not only builds locally, but actively probes and verifies the live running services, database connectivity, and security perimeters before considering the deployment successful.

## Remaining risks
In live staging with custom domains and TLS reverse proxies, `APP_URL` and `LIVE_WS_URL` must point to the public domain (e.g. `https://staging.samjuniors.com` and `wss://staging.samjuniors.com`). The verification runner supports `--url` and `--ws-url` to probe external endpoints seamlessly.
