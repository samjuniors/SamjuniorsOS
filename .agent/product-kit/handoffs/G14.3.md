# G14.3: Skills loader for the SKILL.md format: versioned, reviewed, loaded on demand; skills are instructions, never authority

Exit evidence required: Loads a skill by name and description; a skill cannot grant permissions; activation needs a review record; version pinned. Follow the open Agent Skills spec (agentskills.io); treat community skills as untrusted.

## Plan
1. Define Agent Skills standard schemas (`agentskills.io`) in `src/types/skill.ts` (`SkillFrontmatterSchema`, `SkillReviewRecordSchema`, `SkillDefinition`).
2. Enforce invariant that skills cannot declare or grant permissions; reject any frontmatter declaring `permissions`, `privileges`, or `roles`.
3. Implement `SkillLoader` and `SkillReviewStore` in `src/lib/server/capabilities/skill-loader.ts` with zero-dependency frontmatter parser, cryptographic SHA-256 integrity checks, and version-pinned activation requiring approved review records.
4. Integrate with `CapabilityRegistry` and `CapabilityGateway` so activated skills execute as read-only prompt instruction templates with zero authority elevation and immutable audit logging.
5. Create sample skills: core (`.agent/skills/market-intelligence/SKILL.md`) and community (`.agent/skills/community-web-scraper/SKILL.md`).
6. Author comprehensive automated tests in `tests/capabilities/g14_3_skill_loader.test.ts`.
7. Verify typecheck, lint, build, and test suite.

## What changed

- `src/lib/server/capabilities/skill-loader.ts`: Implemented `parseYamlFrontmatter`, `parseSkillMarkdown`, `SkillReviewStore`, and `SkillLoader` with `loadSkillFromFile`, `loadSkillsFromDirectory`, `activateSkill`, `renderSkill`, and registration into `CapabilityRegistry`.
- `.agent/skills/market-intelligence/SKILL.md`: Core first-party skill adhering to `agentskills.io`.
- `.agent/skills/community-web-scraper/SKILL.md`: Community skill demonstrating untrusted default tier and quarantine.
- `tests/capabilities/g14_3_skill_loader.test.ts`: 17 automated tests verifying YAML parsing, loading by name/description, rejection of permission grants, review record requirement, pinned semver, tampering detection, community quarantine, and `CapabilityGateway` execution with audit logging.

## Why
Per `AGENTS.md` and Milestone M6, skills are instructions for reasoning and prompt guidance, NEVER authority. To prevent capability poisoning or ambient authority elevation from third-party or untrusted skills, skills cannot grant permissions, must be version-pinned, must be verified against an approved review record via SHA-256 content hashes, and community skills must default to quarantined untrusted tier.
