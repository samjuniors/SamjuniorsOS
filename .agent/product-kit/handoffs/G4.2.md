# G4.2: First-class versioned Artifact model

Exit evidence required: Artifact model with versions, provenance and approval linkage; tests; no fabricated artifacts.

## Plan
1. Create `src/types/artifact.ts` defining:
   - `ArtifactKind`: 'PRD' | 'ARCHITECTURE' | 'FINANCIAL_MODEL' | 'EXECUTIVE_REPORT' | 'DECISION_MEMO' | 'SOP' | 'CODE_DELIVERABLE' | 'RESEARCH_BRIEF'.
   - `ArtifactProvenance`: creator identity, creator role, workflowInstanceId, stepId, agentRunId, inputFingerprint, contentHash (SHA-256), createdAt.
   - `ArtifactApprovalLinkage`: bound `FounderApprovalRecord` linkage with `boundPayloadHash` check against artifact content hash.
   - `ArtifactVersionRecord` and `ArtifactRecord`: immutable version array (v1, v2, ...), lifecycle status, slug, and evidence references.
   - Zod validation schemas for input checking.
2. Implement `src/lib/server/artifacts/artifact-store.ts`:
   - Singleton store backed by collection-locked `DurableFileStore` (`artifacts` collection).
   - Methods: `createArtifact`, `addVersion`, `getArtifact`, `getArtifactVersion`, `listArtifacts`, `bindApproval`, `updateStatus`.
   - Automatic SHA-256 content hashing and fail-closed payload alignment validation during approval binding.
3. Wire into `CompanyBrain` as the single authoritative company truth path (`src/lib/server/brain/company-brain.ts` & `src/types/brain.ts`):
   - Expose versioned artifact operations through `CompanyBrain`.
4. Register API route `src/app/api/artifacts/route.ts` and Express adapter in `src/server/api.ts` (`/api/artifacts`):
   - Supports GET (by ID, slug, version, list with filters) and POST (create, add_version, bind_approval).
5. Add automated verification suite `tests/platform/artifact_model.test.ts`:
   - Creation of v1 with SHA-256 content hash.
   - Rejection of duplicate slugs.
   - Addition of v2 without mutating v1.
   - Approval binding with matching payload hash.
   - Rejection of approval binding with mismatched/fraudulent payload hash.
   - Retrieval and filtering by ID, slug, kind, and status.
   - Durability across clean singleton reset / simulated process restart.
6. What will NOT be done: No database schema migration required (persisted durably with collection locks); no bypass of founder authentication.

## What changed
- Created `src/types/artifact.ts` defining first-class typed artifact records, provenance, and approval linkage contracts.

- Integrated artifact store into `CompanyBrain` (`src/lib/server/brain/company-brain.ts` and `src/types/brain.ts`).
- Created `/api/artifacts` endpoint in `src/app/api/artifacts/route.ts` and registered in `src/server/api.ts`.

- Created comprehensive automated test suite `tests/platform/artifact_model.test.ts`.

Delivers a first-class, tamper-evident deliverable lifecycle in SamJuniorsOS where every executive deliverable (PRDs, financial audits, architecture ADRs) is tracked across immutable versions with cryptographic provenance and authoritative founder approval binding.
