## What changed
- `src/types/autonomy.ts`: Defined `AutonomyLevel` (`'L0' | 'L1' | 'L2' | 'L3' | 'L4'`), `AutonomyActionClass` (`read`, `draft`, `internal_write`, `external_reversible`, `external_hard_to_reverse`, `financial_legal`, `destructive_security`), `AutonomyDecisionEffect` (`'auto' | 'needs_approval' | 'forbidden'`), `AutonomyPolicyRule`, `RollingActionBudgetRecord`, and `AutonomyEvaluationResult`.
- `src/lib/server/authorization/autonomy-policy.ts`:
  - Built `AutonomyPolicyEngine` singleton providing deterministic evaluation of Action Class x Autonomy Level x Resource Limits.
  - Initialized with ratified `G0.7` baseline policy table (e.g. `read`/`draft` at L3 auto; `internal_write` at L2 needs approval; `destructive_security` at L0 forbidden).
  - Implemented rolling sliding-window action budgets (borrowed from Latch / AgentPolicy / AgentLedger open-source patterns) tracking consumption per role and action class within time windows, transitioning to `needs_approval` (`AUTONOMY_BUDGET_EXCEEDED`) upon exhaustion.
  - Implemented fail-closed elevation policy in `setAutonomyLevel`: strictly requires authenticated Founder session, valid recorded Founder decision ID, and Founder quote. LLM models, non-founder callers, and AI personas are strictly blocked with `UnauthorizedAutonomyMutationError`.
  - Integrated with immutable audit store (`InMemoryAuditStore`) emitting cryptographic SHA-256 hash-chained `autonomy.level_update` records on level change.
  - Implemented `mapSideEffectToAutonomyActionClass` mapping from route and side-effect classes (`RouteSideEffectClass`, `SideEffectClassification`).
- `src/lib/server/authorization/policy-evaluator.ts`:
  - Exposed `evaluateAutonomy(context)` on `SideEffectPolicyEvaluator` delegating to `AutonomyPolicyEngine.evaluate()`.
- `src/types/authorization.ts`: Added `'FOUNDER_AUTONOMY_LEVEL_UPDATED'` to `AuthorizationReasonCode`.
- `tests/sophia/g12_4_autonomy_policy.test.ts`:
  - Authoring comprehensive 6-phase test suite covering:
    - Phase 1: 35-case table-driven matrix (7 action classes x 5 autonomy levels).
    - Phase 2: Ratified G0.7 baseline table conformance.
    - Phase 3: Rolling sliding-window action budgets consumption and window reset.
    - Phase 4: Model and AI employee persona mutation blocking.
    - Phase 5: Authenticated Founder elevation and hash-chained audit record logging.
    - Phase 6: `SideEffectPolicyEvaluator` integration and classification mapping.

## Why
- Closes Gate G12.4 in Milestone M4. Fulfills Founder Decision G0.7 establishing Sofia's deterministic autonomy boundaries.
- Models and probabilistic components must never be able to elevate their own operational autonomy or bypass approval gates.
- Rolling sliding-window action budgets prevent runaway loops or agent drift when operating at elevated autonomy levels (L3).
