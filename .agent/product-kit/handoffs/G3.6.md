## What changed
- Added sequence, previous-record SHA-256 and record SHA-256 fields to audit records; the canonical hash covers the complete record except its own hash.
- Audit file reads, filtered reads, reloads and appends verify the complete chain. Missing links, gaps and tampered content throw before data is returned or appended.
- Audit appends serialize under the existing durable collection lock. The authoritative Prisma path uses the existing distributed lease with a unique holder and fails closed when it cannot acquire it.
- Prisma stores the full sealed record in the existing JSON payload column, with its existing relational columns cross-checked on read; no schema migration was added.
- Routed spend-setting audit writes through the audit store and added regression coverage for concurrent local appends, tampering, legacy unchained records, and file/Prisma memory-deletion checks.

## Why
- An append-only collection without integrity verification cannot detect edited, missing or reordered records. Reads and appends now stop if the chain does not verify.
- Legacy records have no trusted cryptographic anchor. The system preserves them and refuses reads/appends; it never silently hashes or reseals that unauthenticated history. Recovery requires preserving a byte-for-byte backup, independently checking it against a trusted export/backup, then a founder-reviewed one-time migration with an explicit anchor before reopening the ledger.
- The existing conversation tombstone tests verify anti-resurrection across interrupted Prisma mirror deletion, and the personal-memory test now checks durable-file removal plus Prisma removal when that optional database is available.

- Historical unchained audit rows will stop audit-store reads and writes until a founder-reviewed anchored recovery is completed. Automatic resealing is intentionally prohibited because it could certify already-tampered history.

- Prisma execution was not available here. Authoritative lease acquisition and mirror cleanup need runtime verification against a configured database.
- Audit records remain append-only with no pruning policy; retention remains indefinite under the current immutable-ledger invariant.
