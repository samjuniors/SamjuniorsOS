# G2.4: Multi-instance concurrency: shared leases replace the PID guard

Exit evidence required: Two instances against one database pass the concurrency suite; the PID guard is no longer load-bearing.

## Plan
1. Decouple `InstanceConcurrencyGuard` from load-bearing single-process PID checks on `.data/instance.lock`.
2. Implement shared distributed lease methods in `InstanceConcurrencyGuard` (`acquireSharedInstanceLease`, `releaseSharedInstanceLease`, `startDatabaseHeartbeat`, `stopDatabaseHeartbeat`, `isPidGuardLoadBearing`) operating on the `distributed_leases` table via `LeaseManager`.
3. Enhance `PostgresLeaseManager` (aliased as `DatabaseDistributedLeaseManager`): allow same-holder re-acquisition/extension, handle concurrent write conflicts cleanly via atomic non-blocking statements without interactive connection locks.
4. Harden `PostgresApprovalStore.consume()` with atomic conditional updates against double-consumption across concurrent instances.
5. Author dedicated multi-instance concurrency test suite `tests/platform/multi_instance_concurrency.test.ts` covering:
   - Two instances mutual exclusion against one database via shared lease
   - Heartbeat renewal extending lease TTL
   - Crash failover on TTL expiry without PID inspection
   - Graceful handover
   - 20-worker concurrent acquisition stampede (at-most-one guarantee)
   - Multi-worker scheduled work coordination
   - Multi-instance approval single-action consumption
   - Cross-process real subprocess SIGKILL crash and standby takeover
6. Verify existing regression suites (`m2_batch3_concurrency_hygiene`, `m2_batch3_recovery_gate`, `store_migration_parity`, `versioned_migrations`, `staging_reachability`), run typecheck and lint.

## What changed
- `src/lib/server/persistence/instance-guard.ts`:
  - Added `acquireSharedInstanceLease`, `releaseSharedInstanceLease`, `startDatabaseHeartbeat`, `stopDatabaseHeartbeat`.
  - Added `isPidGuardLoadBearing(): boolean` returning `false`, decoupling concurrency from local OS process PIDs.
  - Updated deployment constraint documentation explaining M2 database-backed lease coordination.
- `src/lib/server/coordination/lease-manager.ts`:
  - Upgraded `PostgresLeaseManager.acquire()` to use atomic queries, eliminating interactive transaction callback timeouts in SQLite.
  - Added same-holder lease re-acquisition and renewal support.
  - Added `DatabaseDistributedLeaseManager` export alias.
  - Added `forceDatabase` option to `getLeaseManager()`.
- `src/lib/server/authorization/approval-store.ts`:
  - Hardened `PostgresApprovalStore.consume()` with atomic conditional SQL update to prevent concurrent double-consumption.
  - Exported `ApprovalAlreadyConsumedError`.
- `tests/platform/multi_instance_concurrency.test.ts`:
  - 9-test multi-instance concurrency suite verifying shared leases, crash failover, 20-worker stampede, approval consumption, and real subprocess SIGKILL takeover.
- `tests/platform/versioned_migrations.test.ts` & `tests/platform/staging_reachability.test.ts`:
  - Normalized SQLite file URLs to absolute path to prevent Windows Error 14 in test suites.

## Why
Under Milestone M2 (Phase 2.3B / Option A), SamJuniorsOS runs as an always-on system with shared persistence in the database (SQLite volume / target PostgreSQL). Local PID file checks are ineffective across containers, VMs, and multiple processes. Shared distributed leases in the database guarantee safe mutual exclusion, scheduled task partitioning, and crash recovery purely via lease expiration timestamps (`expiresAt`) without relying on local OS process inspection.

## Remaining risks
In high-concurrency environments on SQLite (Option A), burst write traffic is serialized by SQLite file locking. Handled gracefully by atomic conditional queries without long-lived interactive transaction locks. Target PostgreSQL migration (M6) will seamlessly inherit this with row-level locks.
