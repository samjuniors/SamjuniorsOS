## Plan
1. Add `sourceIds?: string[]` to `SophiaContextSlice`, `SophiaAssembledContext`, and `SophiaTurnResult` in `src/lib/server/sophia/types.ts`.
2. Update `SophiaContextAssembler.assemble` to populate `sourceIds` for every recalled slice (operational state, active workflows, approvals, canonical facts, superseded facts, dependency path, unverified claims, company knowledge, company precedent, recent activity, personal mind, and episodic memory).
3. Thread `sourceIds` through `executeSophiaTurn`, persisting `sourceIds` in `ChatMessageRecord.metadata` and returning `sourceIds: []` on honest abstention.
4. Expose `sourceIds` in SofiaUI and SSE streaming endpoints.
5. Create comprehensive test suite `tests/sophia/g11_3_scope_aware_retrieval.test.ts` verifying benchmark baseline integrity, source ID attribution across scopes, and honest abstention.
6. What will not be done: will not alter the existing zero-failure retrieval benchmark fixture or modify routing semantics.

## Smallest-change ladder
Needed: Scope-aware retrieval requires transparent, machine-verifiable provenance (source IDs) on every recalled item so Sophia never hallucinates citation origins, respects partition budgets, and abstains honestly when empty.
Already in codebase: `SophiaContextAssembler` with authority partitions (`CANONICAL_FACT`, `PERSONAL_MIND_MEMORY`, `COMPANY_KNOWLEDGE`, etc.), `ci-baseline.json` with baseline `M5.3-A3`, and honest abstention checks in `SophiaTurnExecutor`.
Platform or dependency: TypeScript interfaces, Set deduplication, JSON metadata persistence in Prisma/SQLite ConversationStore.
Not built: Vector embeddings or external vector database; deterministic ranking and lexical retrieval already provide zero regressions on the authoritative benchmark.
Added: `tests/sophia/g11_3_scope_aware_retrieval.test.ts` (test suite covering benchmark baseline, source ID attribution, partition boundaries, and honest abstentions).
