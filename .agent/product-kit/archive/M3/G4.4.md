# G4.4: Memory retrieval benchmark as a regression gate in CI

Exit evidence required: Existing benchmark runs in CI with a recorded baseline and a failing threshold.

## Plan
1. Establish authoritative recorded baseline: `benchmark/memory-retrieval/ci-baseline.json`:
   - Records baseline `M5.3-A3` verified zero-failure state.
   - Pinned SHA-256 fixture digest (`40e53f1581def28371af8f050bc5ba85eaf58a47cbb86a4f449fad1beef719fb`).
   - Query count: 13.
   - Failing thresholds:
     - `maxOverallFailures`: 0
     - `minOverallRenderRecall`: 1.00 (100% of gold items must render in assembled context)
     - `minOverallUnionRecall`: 0.90 (baseline is ~0.921)
     - `maxAuthorityFailures`: 0
     - `maxGraphCandidateFailures`: 0
     - `maxBoundaryViolations`: 0 (personal/company boundary leak)
     - `maxFounderScopeViolations`: 0 (cross-founder leak)
     - Per-category threshold bounds for all 8 benchmark categories.
2. Build executable regression gate engine: `benchmark/memory-retrieval/verify-ci-gate.ts`:
   - Executes deterministic retrieval battery across all 13 queries.
   - Evaluates run results against `ci-baseline.json`.
   - Exits with code 0 on PASS; exits with code 1 and detailed regression diff on FAIL.
   - Exports `evaluateAgainstBaseline` and `runBenchmarkCli` for automated testing.
3. Integrate into CI and npm scripts:
   - Add `"benchmark:memory": "node --import tsx benchmark/memory-retrieval/verify-ci-gate.ts"` to `package.json`.
   - Add step `Memory retrieval benchmark regression gate (G4.4)` to `.github/workflows/ci.yml`.
4. Automated verification suite: `tests/platform/memory_benchmark_gate.test.ts`:
   - Validates baseline configuration integrity.
   - Verifies real benchmark execution against production stores passes all thresholds.
   - Verifies fail-closed behavior on simulated failure regression, union recall drop, render recall drop, boundary leak, and fixture digest mismatch.

## Why
Without an automated regression gate in CI with recorded baselines and failing thresholds, future changes to memory storage, context assembly, or token pruning could silently degrade recall or leak cross-boundary data without breaking ordinary unit tests. Enforcing a zero-failure, 100% render recall gate directly in CI guarantees deterministic quality across all company and personal memory retrieval paths.
