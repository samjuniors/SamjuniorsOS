# G4.3: GitHub adapter with idempotency key and unknown-outcome handling

Exit evidence required: Duplicate delivery produces one effect; unknown outcome is surfaced, not assumed; tests.

## Plan
1. Implement `src/lib/server/integrations/github-adapter.ts`:
   - Strict idempotency key claims via `IdempotencyStore`.
   - Deterministic SHA-256 payload hashing for issue creation requests (`hashPayload`).
   - Duplicate delivery prevention: duplicate delivery of API commands returns cached response; duplicate webhook deliveries return `{ status: 'duplicate' }` with zero extra side effects.
   - Unknown-outcome classification: 5xx responses, timeouts, and network drops (e.g., connection drops) are transitioned to `'unknown'` in `IdempotencyStore` and throw `UnknownExternalResultError`. Blind retries are blocked until reconciled.
   - Reconciliation engine: `reconcileUnknownOperation(key)` probes remote GitHub API state to determine if the issue actually landed remotely.
   - Webhook epistemic ingestion: verified webhook events are recorded into `CompanyBrain` as authoritative intelligence.
2. Implement automated verification test suite `tests/platform/github_adapter.test.ts`:
   - 4.3.1 Creates issue and caches result for identical idempotency keys (single external dispatch).
   - 4.3.2 Rejects payload mismatch when reusing explicit idempotency key (`IdempotencyPayloadMismatchError`).
   - 4.3.3 External 5xx / network errors transition to unknown and throw `UnknownExternalResultError` (blocking blind retries).
   - 4.3.4 Reconciles unknown operation by probing remote GitHub state.
   - 4.3.5 Ingests webhooks idempotently and produces exactly one mutation / duplicate delivery detection.
   - 4.3.6 Deterministic client error (4xx) marks record failed, not unknown.
3. Verify with full test suite, typecheck, lint, secret scan, and smoke test.

## What changed

## Why
External third-party API mutations (such as GitHub issue creation and webhook processing) can experience transient network interruptions or timeouts where the HTTP response is lost even though the mutation succeeded upstream. Treating network drops as failures causes duplicate tickets and divergent state; treating them as successes causes missing artifacts. Enforcing strict idempotency keys with explicit `unknown` state transitions and reconciliation guarantees deterministic company operational truth.
