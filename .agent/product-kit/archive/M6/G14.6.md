## Plan
1. Define integration contracts and schemas in `src/types/integrations.ts` for the 3 founder-selected integrations:
   - GitHub (code host: issue creation and repo read)
   - Resend (email: transactional dispatch)
   - Stripe (payments: payment intents and customer billing)
   - Integration errors: `IntegrationValidationError`, `IntegrationAuthError`, `IntegrationRateLimitError`, `IntegrationServerError`.
2. Implement `ResendAdapter` in `src/lib/server/integrations/resend-adapter.ts`:
   - Contract validation with Zod.
   - Idempotency key tracking via `IdempotencyStore`.
   - Failure mode handling (4xx vs 5xx/network errors).
   - Unknown-outcome handling (`UnknownExternalResultError`) and truthful remote reconciliation (`reconcileOutcome`).
3. Implement `StripeAdapter` in `src/lib/server/integrations/stripe-adapter.ts`:
   - Contract validation with Zod.
   - Idempotency key tracking via `IdempotencyStore`.
   - Failure mode handling (4xx card/client errors vs 5xx/network drops).
   - Unknown-outcome handling (`UnknownExternalResultError`) and truthful remote reconciliation (`reconcileOutcome`).
4. Register the 3 integrations in `CapabilityRegistry` (`src/lib/server/capabilities/capability-registry.ts`) and verify policy rows in `AutonomyPolicyEngine`:
   - `tool:github:create_issue` -> `external_reversible` (L2, approval-by-default)
   - `tool:resend:send_email` -> `external_hard_to_reverse` (L2, approval-by-default)
   - `tool:stripe:create_payment_intent` -> `financial_legal` (L1, approval-by-default)
5. Author comprehensive automated tests in `tests/integrations/g14_6_first_integrations.test.ts`:
   - Contract tests for each integration (GitHub, Resend, Stripe).
   - Failure-mode tests for each integration (validation, auth, rate limit, server error, network timeout).
   - Policy row (approval-by-default) tests verifying that invoking each side-effect capability via `CapabilityGateway.invoke` halts in `awaiting_founder_approval`.
   - Unknown-outcome tests for side-effect operations verifying network drops transition to `unknown`, reject blind retries, and reconcile truthfully.
6. Verify typecheck, lint, build, canonical test runner, review, and land.

## What changed
1. Contract Types and Error Hierarchy (`src/types/integrations.ts`):
   - Defined `IntegrationError`, `IntegrationValidationError`, `IntegrationAuthError`, `IntegrationRateLimitError`, `IntegrationServerError`.
   - Defined Zod schemas and TypeScript interfaces for Resend email dispatch (`ResendEmailInputSchema`, `ResendEmailResultSchema`) and Stripe payment intent creation (`StripePaymentIntentInputSchema`, `StripePaymentIntentResultSchema`).
2. Resend Adapter (`src/lib/server/integrations/resend-adapter.ts`):
   - Implemented `ResendAdapter` with strict contract validation, distributed `IdempotencyStore` key tracking, deterministic 4xx vs 5xx/network error classification, fail-closed handling, `UnknownExternalResultError` on network drops/504 timeouts, and truthful `reconcileOutcome`.
3. Stripe Adapter (`src/lib/server/integrations/stripe-adapter.ts`):
   - Implemented `StripeAdapter` with strict contract validation, distributed `IdempotencyStore` key tracking, deterministic 4xx (including 402 card errors) vs 5xx/network drop classification, `UnknownExternalResultError` on network drops, and truthful `reconcileOutcome`.
4. Core Capability Registration & Secrets (`src/lib/server/capabilities/capability-registry.ts`, `src/lib/server/capabilities/secret-vault.ts`):
   - Registered `tool:github:read_issue` (`read_only`), `tool:github:create_issue` (`external_reversible`), `tool:resend:send_email` (`external_hard_to_reverse`), and `tool:stripe:create_payment_intent` (`financial_legal`) under core capabilities.
   - Wired vault secrets `GITHUB_TOKEN`, `RESEND_API_KEY`, and `STRIPE_SECRET_KEY` strictly scoped to their respective capability IDs.
5. Automated Test Suite (`tests/capabilities/g14_6_first_integrations.test.ts`):
   - Authored 14 automated tests covering:
     1. Contract tests (schema & payload validation) for GitHub, Resend, and Stripe.
     2. Failure-mode tests (400 validation, 401 auth, 402 card error, 429 rate limit, 500 server error) with deterministic typed error classes.
     3. Policy rows and approval-by-default governance verifying side effects halt in `awaiting_founder_approval` with an immutable cryptographic `ApprovalRecord`, while read-only tools execute autonomously.
     4. Unknown-outcome and distributed idempotency tests for side-effect integrations (GitHub, Resend, Stripe) verifying network drops transition to `unknown`, block blind retries, and reconcile truthfully.

## Why
Per `AGENTS.md` Sections 4, 5, 11, and 12, external integrations must never be allowed to produce unapproved side-effects or perform blind duplicate retries on network failures. Each integration must have strict contracts, deterministic failure handling, approval-by-default governance, and distributed unknown-outcome safety.
