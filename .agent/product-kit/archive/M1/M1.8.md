## What changed
1. `src/lib/server/sophia/spend-settings.ts`:
   - Created `SpendSettingsManager` singleton persisting to existing `company_state` collection in `DurableFileStore`.
   - Guaranteed that an unset cap (`dailySpendCapUsd: null`) strictly blocks autonomous spend (`canExecuteAutonomousSpend().allowed === false`).
   - Tracked interactive spend vs autonomous spend with daily reset capability.
   - Implemented `stopRunningTasks()` and hooked into `SafeModeManager` so reaching or lowering the cap immediately halts running tasks.
   - Logged every change by the Founder into the durable audit ledger (`audits.json`).
2. `src/lib/server/sophia/index.ts`:
   - Exported `spend-settings` module.
3. `src/lib/server/workflow/scheduler.ts`:
   - Added `SpendSettingsManager.getInstance().canExecuteAutonomousSpend()` gate at the top of `evaluateDueWork()`.
4. `src/lib/server/sophia/turn-executor.ts`:
   - Added interactive spend gate: if spend cap is reached, halts turn and responds with explicit COO refusal citing limit.
   - Recorded incremental interactive spend upon turn completion.
5. `src/app/api/sofia/spend/route.ts` & `src/app/api/sophia/spend/route.ts`:
   - Exposed authenticated GET and POST endpoints for managing spend settings.

   - Added "Spend & Autonomy Limits" accordion section with real-time spend cards and interactive cap controls.
7. `tests/sophia/m1_8_spend_settings.test.ts`:
   - 16 assertions across 6 test groups verifying unset cap blocks autonomous spend, interactive spend counting, cap breach stoppage, task cancellation upon lowering cap, durable audit logging, and authenticated API routes.
