# G0.3 brief: infrastructure (hosting, database, recovery, budget)

Status: DRAFT for the founder's decision, prepared 2026-10-20. Prices change; every price here must be re-checked on the provider's page when you decide. Labels: Verified, Reported, Inference, Unknown.

## Decision needed
Hosting model, database, recovery targets (RPO and RTO), backup retention, and budget. `doc/PRODUCT_ARCHITECTURE.md` section 0 blocks persistence work until this is decided, and Phase 2.3C is unauthorized until then.

## What the approved design already says
- **Verified:** `docs/architecture/PHASE_2_3B_...` section 9 compares four options. Its verdict (9.1): SQLite is "fully appropriate for production" on a single pinned instance with attached persistent storage. PostgreSQL is mandatory only for multi-instance scaling, zero-downtime rolling deploys or serverless.
- **Verified:** today the app uses SQLite through Prisma plus local JSON collections under `.data/`. The JSON collections are the real durability gap. `DurableFileStore` writes under `.data/` and falls back to the OS temp directory.
- **Verified:** retention, PITR window, RPO and RTO are marked founder decisions. The design's numbers (daily snapshots for 30 days, an annual snapshot for a year, 7-day point-in-time recovery) are illustrative only.

## Your facts
You are the only user (G0.1). You want Sofia to run the company and to control your Windows PC. A PC that is off or asleep cannot run a company.

## Options
| | What | Cost (repo's estimate) | Reported 2026 figures |
|---|---|---|---|
| **A. One always-on host, SQLite** | One container on a small VPS with a persistent volume | $5 to $20 a month | A small VPS is about EUR 5 to 8 all-in with snapshots (a July 2026 post by one author) |
| **D. One always-on host, Docker Compose with PostgreSQL** | Same host, Postgres in a container | $15 to $35 a month | Same host class |
| **B. Container runtime plus managed PostgreSQL** | Cloud Run style plus Neon, Supabase or RDS | $30 to $110 a month | Neon: no minimum, about $0.106 per compute-hour and $0.35 per GB-month, so one always-on unit is roughly $76 to $78 a month; Supabase Pro $25 plus compute |
| **Local only** | Everything on your Windows PC | none | Sofia stops when the PC sleeps; no phone access |

## Recommended default (Inference): A, with the Windows PC as an audio and actuator node
Why: the repository's own verdict allows it, it is the cheapest, it is the smallest change (no migration of the database engine), and it matches a single founder. Moving the JSON collections into the database and adding tested backups are still required. Scale-to-zero pricing helps little here, because a company that runs around the clock keeps the database awake.

If you pick A, the kit's gate plan shrinks: G2.2 becomes versioned SQLite migrations, and G2.4 (multi-instance leases) is not needed. If you pick B or D it stays as written.

## Recovery targets (you choose; these are menus, not recommendations)
- **RPO** (how much data you can lose): about a day (daily backup), about an hour (hourly snapshot plus off-site copy), or minutes (continuous log archiving, which needs PostgreSQL).
- **RTO** (how long she may be down): a day, a few hours, or under an hour. A tested rebuild script sets what is real.
- **Retention:** how many daily copies and how long to keep a yearly one, balanced against storage cost and any deletion obligations.

## The attack
- One host is one failure point. It is acceptable only if backups are tested by restoring them, which G2.5 requires.
- Choosing A now and PostgreSQL later is a real migration project (the design calls it Phase 2.3C). Gate G2.7 (scale-later seams) lowers the cost but does not remove it.
- Operating a server yourself means patching, firewalling and monitoring. Managed services remove that for a monthly fee. For a single founder that fee may be worth it. That is a judgment about your time, not a technical fact.

## What would change this
A need for zero-downtime deploys, more than one founder, or a data-residency requirement; unwillingness to run a server.

## Questions for you
1. Must Sofia work while your PC is off?
2. How much data loss can you tolerate (RPO), and how long can she be down (RTO)?
3. What is the monthly infrastructure budget, separate from model spend?
